BigQuery proves your data is fresh, complete, unique, and structurally valid. None of that catches the pipeline that silently drifts in meaning. Semantic Drift Sentinel treats semantic quality as a continuous infrastructure metric, with a circuit breaker at the gate.

The pattern

Five layers, top to bottom. Click any layer.

The whole point: at scale the model call is the easy part. The hard part is the engineering boundary around it — concurrency throttling, retries, idempotency, and absolute cost control. Keep the expensive semantic check for only the rows that need it.

1

BigQuery — Ingestion & filtering

deterministic SQL

Run the cheap, deterministic checks first (freshness, completeness, schema, uniqueness). Route only high-risk or sampled rows out of the warehouse — never pay to semantically score everything.

In the repowarehouse.py (DuckDB stand-in) + bigquery/01_deterministic_checks.sql
Outputfiltered / sampled high-risk rows
2

Cloud Run — Async compute adapter

batching · retries · throttle

An asynchronous Python service manages batching, exponential-backoff retries, idempotency, and a strict concurrency cap — the real engineering so a spike never melts the budget or trips rate limits.

In the repoadapter.py — runs in-process for the demo, or as FastAPI (make serve)
ControlsMAX_CONCURRENCY · BATCH_SIZE · MAX_RETRIES
3

Jev — TypeSafe semantic evaluation

state + questions → typed answers

Batched rows go to the evaluation layer for model inference and strict structural JSON scoring. Every answer validates against a typed contract (Noul / Choice / Score with calibrated probabilities) — no free text to parse.

In the repoevaluator/ (jev) + schemas.py
Question"Does the resolution_summary actually address the ticket?"
4

Data circuit breaker

semantic thresholds

Apply thresholds at the gate. If semantic quality drops too far versus the baseline — or below an absolute floor — instantly trip: fire a downstream alert and route anomalies to a human review queue.

In the repocircuit_breaker.py
Trips ondrift > 0.15  OR  mean quality < 0.70
↯ alert

Downstream pipeline alert (Slack / PagerDuty)

◷ review

Worst rows → human review queue

5

Closed loop

versioned metrics

Continuously write versioned quality metrics back into BigQuery to trace and track long-term semantic drift by deployment — turning a one-off check into a monitorable time series.

In the repowarehouse.py + bigquery/02_quality_metrics_schema.sql
Enablesdrift-by-version trend, cost per loop, disagreement rate

The typed boundary

One judge: Jev.

Jev returns answers that validate against a typed schema, so the pipeline never parses free text. The boundary in schemas.py is deliberately backend-agnostic, so the evaluator can be swapped without the rest of the pipeline moving.
